# Changes Made on 2026-03-25

Date: 2026-03-25

## Overview

Today's work focused on hardening the frontend/backend integration for AgenticNetSec so the UI reflects backend truth more accurately and the async job flow is more resilient for demo and audit use.

The implementation addressed the main integration gaps identified during repository review:

- in-memory-only job history
- placeholder pipeline progress (`pipeline` / `0.2`) rather than real phase updates
- artifact views that stalled on `409 not ready`
- Windows API startup issues caused by always-on `reload=True`
- missing surfaced metadata for file size, capture window, packet count, flow count, runtime, confidence, and risk

## Backend Changes

- Extended the job status schema to include additive fields for:
  - source type/name/path
  - created and updated timestamps
  - metadata block
  - artifact readiness flags
  - attack type, risk level, confidence score, and runtime summary
- Extended the forensic report header to include a metadata block containing:
  - filename
  - resolved path
  - size in bytes
  - packet count
  - flow count
  - capture start/end timestamps
- Updated the analysis engine so it now emits backend-driven progress callbacks for:
  - ingest
  - parse
  - analysis
  - reason
  - report
- Updated API job execution so failed jobs preserve the last active phase/progress instead of collapsing into a generic placeholder state.

## Persistence and API Flow Changes

- Reworked `backend/api/job_store.py` to persist each job as `outputs/analysis_jobs/<job_id>/job.json`.
- Added startup rehydration so persisted jobs are loaded back into memory when the API starts.
- Added artifact readiness tracking for:
  - `report.json`
  - `report.md`
  - `metrics.json`
  - `guardrail_audit.json`
- Updated `POST /api/v1/analysis` and `GET /api/v1/analysis/{job_id}` so they now return richer status payloads.
- Updated `GET /api/v1/analysis` to expose the same richer metadata for history views.
- Removed the debug `print()` from the job-listing endpoint.

## Runtime and Startup Changes

- Changed `backend/scripts/run_api.py` so `reload=False` is now the default.
- Added explicit CLI flags for:
  - `--host`
  - `--port`
  - `--reload`
- This makes the API runner stable by default on Windows while keeping auto-reload available for development.

## Frontend Changes

- Extended frontend transport and domain types to consume the richer job status payload.
- Updated adapter logic to normalize:
  - metadata
  - artifact readiness
  - runtime/risk/confidence summary values
- Updated the job detail page to display backend-owned information for:
  - source metadata
  - packet/flow counts
  - capture window
  - runtime
  - risk
  - confidence
  - artifact readiness
- Replaced the old synthetic timeline interpretation with backend-driven phase rendering.
- Updated the report page to:
  - show report metadata in the summary block
  - poll while the job is still running
  - offer retry/refresh actions when `report.json` is not ready yet
- Updated the raw artifacts page to:
  - poll while artifacts are still pending
  - offer retry/refresh actions per artifact tab
  - preserve existing metrics and guardrail views
- Updated the history page to add:
  - source column
  - risk column
  - confidence column
  - runtime column
  - search input
  - status filter
- Extended shared formatting and status display helpers to support:
  - byte formatting
  - phase label formatting
  - additional badge states
